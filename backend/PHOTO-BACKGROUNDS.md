# Free photo backgrounds

Admin opens Add/Edit jewellery → uploads photos → Background on a photo. Options: Warm Cream (canvas gradient) and Midnight Blue Velvet (generated empty background asset). Auto cutout is U²-Netp running in a dedicated Web Worker with ONNX Runtime Web 1.22.0, WASM single-threaded. No paid image API and no upload to an external AI service. All runtime/model files are served by this site, loaded only when automatic cutout is requested. Approximate first-use runtime/model download: 15–17 MB; browsers may cache it. Closing the editor terminates the worker; a two-minute timeout permits recovery on slow devices.

The app composites original RGB pixels using an alpha mask; it never generates replacement jewellery. Cutouts can lose thin chain edges or retain glare. Restore/Erase brushes, background-colour removal with tolerance, undo, reset and before/after preview are available. Applying a style requires an explicit review checkbox; failed processing never automatically saves an image. Use original photo restores the original. Presets approximate the examples' backgrounds, not the fully generated preview jewellery/lighting.

Photos are processed from the site's existing compressed uploads (maximum900px long side), not an archival full-resolution camera original. Styled output is JPEG quality0.9; untouched upload compression remains0.78. The original compressed photo is preserved through styling, photo reordering and saving, in jewellery.photo_originals (matching gallery photos by index). Older records fall back to current photos. Saving uploads originals/styled images through existing admin-only storage controls, deduplicates originals already in the gallery, and applies existing failed-write cleanup safeguards. Originals are public catalogue media like other product images but aren't automatically added to the customer gallery. No customer/private documents should be uploaded as jewellery images.

Database migration: photo-originals-schema.sql, applied after made-to-order-schema.sql. Same sole-admin RLS/Storage policies remain in force. No prices, quantities or order workflow changes.

Licences: model Apache-2.0 with pinned provenance/hash in dist/models/NOTICE.md; ONNX runtime MIT plus bundled third-party notices in dist/vendor/onnx. Empty velvet background was generated for this shop; cream is programmatic. To refresh vendored runtime files after npm ci, run node scripts/copy-photo-runtime.mjs. Retain licence/notice files. User-uploaded example photos are not committed.

Verification: real browser inference tested on the user's thin-chain example (no model mock), both presets, review-gated apply, manual correction, undo, original restoration and cancellation. Product upload/reorder/save flow tested with mocked authenticated storage responses; original/styled URL mapping tested in npm test. Actual owner-session storage writes remain for the shop to try. Source/background changes are pushed to LKJ and published through Sites.
